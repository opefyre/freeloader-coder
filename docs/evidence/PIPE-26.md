# PIPE-26 acceptance evidence

## AC1 — Standard-mode comprehension

Foundation baseline passes against observed target-user feedback:

- Familiar Git, diff, test, build, API-key, and repository language is retained.
- Infrastructure and orchestration terms move behind Advanced details.
- Failure messages lead with consequence, preserved state, uncertainty, and
  action.
- The observed target user explicitly rejected generic status language,
  invisible waiting, and infrastructure explanations without repair.

This is not market-wide comprehension validation. Five external sessions remain
a Connected Beta gate.

## AC2 — Evidence-backed strong states

Pass.

`docs/product/state-language.md` defines required postconditions for complete,
fixed, safe, and published. Generation, patch application, command attempts,
and provider acknowledgements are explicitly insufficient.

## AC3 — Cross-surface vocabulary

Pass as a binding Foundation contract.

`docs/product/vocabulary.md` requires the same canonical terms and codes across
UI, notifications, help, support bundles, analytics, accessibility
announcements, and localization. Future implementation tickets must consume
these contracts rather than redefining state language.
