# Provider capacity scheduler

## Outcome

Pipeline Studio plans free-provider work before dispatch. A task is now either:

- dispatchable through an eligible provider with an available safe slot;
- waiting until the earliest known reset or concurrency window; or
- blocked by a permanent policy, configuration, privacy, or compatibility issue.

Waiting is persisted by the provider journal and does not consume task retry
attempts. The runtime does not call providers again before `retryAt`.

## Reliability controls

- Deterministic priority, enqueue-time, and task-id ordering.
- Provider-reported, minute, daily, free-unit, circuit, and concurrency gates.
- Explicit earliest next-eligible time across rejected routes.
- Per-provider batch queues and safe concurrency admission.
- Capacity reservations for review work so implementation cannot starve QA.
- Paid, unknown-cost, and billing-enabled routes remain denied in free-only mode.
- Permanent blockers remain distinct from temporary capacity waits.

## User visibility

The Providers screen exposes active dispatches, scheduled waits, wake-up times,
protected QA capacity, provider evidence, and the zero-spend routing policy.
The fixture is generated by the production scheduling function rather than
independently hard-coded UI counts.
